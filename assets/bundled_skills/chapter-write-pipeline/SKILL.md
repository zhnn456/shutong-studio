# 章节写作流水线

本指南供执笔作者在生成小说章节正文时使用。目标是把"一次生成整章"改成"先定方案、确认后再写、写完审查、状态回填"，降低返工并避免前后矛盾。

## 流程（顺序执行，不可跳步）

1. **写前简报（先不要写正文）**
   - 先读取本章的章纲/大纲条目（如有）。若本章还没有章纲或仅有标题，先补一份简明章纲：本章目的（只主打一个）、卷入人物及各自状态、冲突/阻力、章末钩子。
   - 然后产出本章「场景清单」：列出 3-5 个场景，每个场景写清 时间地点、视角人物、本场目标推进、冲突/阻力、章末钩子。
   - 用列表输出场景清单，停下来等用户确认或调整后再进入下一步。

2. **起草正文**
   - 按确认后的场景清单逐段写正文。只喂本章所需的上下文（相关人物档案、相关世界观规则、上一章结尾），不把整本书塞进来。
   - 严格遵循专业创作规则：show don't tell、调动五感、对话有潜台词、节奏靠句长、视角全程一致、与大纲严格对应、章末留钩。

3. **审查**
   - 正文完成后自查：① 是否与大纲条目和上一章结尾衔接；② 人物行为是否符合设定档案；③ 该埋/该收的伏笔是否到位；④ 是否存在"说明性对话、AI 腔"（如每段都以"突然/瞬间"开头、冲突同章即了）。
   - 输出简短审查结论与问题点，有问题先改再交付。

4. **沉淀（写后回填）**
   - 把本章产生的 角色状态变化、新伏笔、未解决线索、设定补充 整理成"待回填清单"（diff 形式：新增/变更项），列出来等用户确认。
   - 确认后，把改动回填到对应的人物库/大纲/设定库；未经确认不要改写已有设定。

## 落盘

按 4 步顺序推进，每一步与用户确认后再进入下一步，不要一口气输出所有步骤。正文落盘到 /chapters 集合对应章节；角色/大纲/设定的回填只在用户确认后执行。
