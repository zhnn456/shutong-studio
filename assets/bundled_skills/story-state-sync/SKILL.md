# 故事状态同步

本指南供编年史者在章节正文完成后回填故事状态使用。核心是"写后回写"：正文一旦发生事实变化，及时把它们落回人物/大纲/设定库，避免长连载遗忘与前后矛盾。

## 流程

1. **读取现状**
   - 先读已有的人物库、大纲与设定库，以及本章正文，核对本章实际发生了哪些事实变化。

2. **生成待回填清单（diff 形式）**
   - 只列有原文依据的变化，不把大纲计划、角色谎言或猜测当事实。
   - 逐项列出：新增项（新登场人物/新伏笔/新设定补充）与变更项（角色状态/关系/位置变化），并标注本章依据。

3. **等用户确认后回填**
   - 把清单列给用户确认，确认后写入对应的人物库/大纲/设定库。
   - 未经确认不要改写已有设定；无法确定后续影响时注明"待核对"，不编造结论。

## 原则

- 只处理本次指定章节范围，先查已有实体，合并仍有效的信息，避免重复创建。
- 不改写正文或大纲，只维护状态文档与实体。
- 完成后简要报告处理范围、实际更新和未解决的连续性问题；工具失败不得声称已保存。
