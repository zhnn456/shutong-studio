# 续作初始化流程

在当前作品上下文中的 `type` 为 sequel 时使用。续作承接的是前作已完成或阶段性收束后的故事；不当作同人，也不问「故事线之前/平行/之后」。

## 1. 建立前作承接边界

先读工作区已有的前作资料、结局、时间线、人物、世界观与大纲。用 AskUser 分轮确认：

1. 承接哪部前作，采用哪个结局、版本或已完成范围
2. 前作中必须保留的结局事实、人物状态、关系、世界规则与未解伏笔
3. 续作与前作相隔多久，是否换主角、换舞台、换核心冲突
4. 前作资料是否足以说明「故事结束时世界处于什么状态」；不足时要求补充，不能自行编造前作结局

将承接边界、不可推翻事实、时间跨度写入工作区资料。只有后续写作必须严格遵守的稳定边界，才经确认后写成 AgentRule。

## 2. 确认续作为什么必须存在

续作不能只重复前作成功模式。确认：

- 前作已经解决了什么，续作不再重复解决什么
- 哪个后果、代价、遗留问题或新变化，使新的主冲突成立
- 新主角或旧主角现在的目标、资源与局限
- 前作读者能获得的延续体验，以及续作新增的核心体验

说不清「前作结局之后为什么仍有必须讲的故事」时，先停在这里澄清，不要急于取名或展开世界观。

## 3. 形成承接大纲

在前作边界与新主冲突确认后，生成候选续作承接大纲，至少包含：

1. 开局时距前作结局的时间与世界状态
2. 前作人物、势力、伏笔在续作中的继承、退场或转化
3. 触发新主线的事件与主角的新目标
4. 与前作主题呼应但不重复的中段升级
5. 续作独立高潮，及其对前作遗留问题的回答

AskUser 确认、修改或重做；确认前不写入。确认后：承接边界写时间线/世界观，续作主线写大纲轨道。

## 4. 交付 L2 骨架（续作版）

按 `SKILL.md` 第 5 节五段执行，差异点：

- **A 世界观 5 条**：必须写清「前作已确立且不可推翻」与「续作新变化」两类，前作规则不得被悄悄改写
- **B 角色 6–8 张**：每张标 `[继承]`/`[退场]`/`[转化]`/`[新增]`；继承角色写明前作结局时的状态与现在的变化；新增角色必须有独立功能位，不能只做前作角色的复刻
- **C 分卷大纲**：每卷标出「回应了前作哪条遗留问题」，避免续作变成平行重写
- **D 逐章纲目**：每章引用里，来自前作的伏笔必须标 `[前作伏笔]`，并注明在前作哪一章埋下
- **E 自检**：SKILL.md 的 7 条 + 追加 2 条：
  6. 没有任何情节直接推翻前作结局事实
  7. 前作遗留伏笔至少有一条在高潮卷回收

## 5. 完成通用初始化

承接边界与新主冲突确认后，再确认题材、读者、故事承诺、书名、分类、标签、简介与通用写作约束（7–10 条 AgentRule）。

## 6. 结束检查

- 前作采用范围与不可推翻事实是否明确？
- 续作是否拥有独立主冲突，而非重复前作？
- 角色、世界、时间线的变化是否与前作结局相容？
- 候选承接大纲是否已确认并落盘？
- **L2 五段是否齐全，自检 9 条是否全过？**
