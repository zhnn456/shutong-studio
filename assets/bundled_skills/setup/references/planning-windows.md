# 分级冻结与规划窗口（本地适配版）

本文件改编自 MyNovel 的《规划窗口与防抢跑》（MIT，见 `third/upstreams/chinese-longnovel-skill/references/规划窗口与防抢跑.md`），按其方法论映射到本应用的卷 / 大纲 / 章节资源，**不是原文照搬**。

## 为什么要有这一层

开书最常见的两个失败方向是相反的：

- **规划太少**：只给几条规则，写到二三十章就开始漂，角色失忆、伏笔断线。
- **规划太死**：一次把 120 章的每一章都写死成剧本，写到第 40 章发现人物走向不对，前面全部作废。

解决办法不是二选一，而是**分层冻结**：远处只锁边界，近处才锁细节。边界的作用是"禁止提前把后面的牌打完"，不是"规定你必须这么写"。

## 三级冻结

| 层 | 冻结什么 | 载体 | 允许改动 |
|---|---|---|---|
| **全书** | 三幕结构、卷数、全书终点、核心能力的上限与代价 | 元数据 + 世界观 `/lore` + 全书总纲 `/outlines` | 极少改；改要显式确认 |
| **卷（窗口）** | 本卷必须完成什么、只能推进什么、**禁止提前完成什么**、必须留给后续卷什么、卷末必须仍然存在的矛盾 | `/outlines` 的卷轨 + `/volumes` 卷节点 | 逐卷确认，改本卷不影响他卷 |
| **章** | 标题、梗概、章纲 | `/chapters` | 当前卷写死；后续卷只到标题+一句话梗概 |

**关键原则：卷合同里的"禁止提前完成"比"必须完成"更重要。** 它防止第 30 章就把第 80 章的高潮用掉，导致后面只能重复升级或提前完结。

## 卷合同（每卷必写，写进该卷大纲轨道的 content）

每卷大纲轨道除原有的"卷目标 / 三步推进 / 卷末反转 / 交接钩"之外，必须再写这 5 项：

| 字段 | 写什么 | 举例 |
|---|---|---|
| **本卷必须完成** | 本卷结束时读者应看到已结算的事件或状态 | 主角拿到通关文牒，使团活着走出天竺 |
| **只推进不完成** | 本卷只能往前走、不许收口的长线 | 主角与阿罗那顺的私仇只加深，不许了结 |
| **禁止提前完成** | 留给后面卷的高潮、解锁、伏笔回收，本卷不许碰 | 禁军内应身份、佛骨真相、主角第一次真正杀人 |
| **留给后续卷** | 明确分配给后面哪一卷的剧情负载 | 第 3 卷：取经队伍成形；第 4 卷：归国清算 |
| **卷末未解决** | 本卷结束时必须仍然悬着的矛盾或债务 | 使团少了 29 人，尸首在哪没查清 |

后三项不许写空、写 `[]`、写"待定"。写不出来说明这一卷没有张力，先补卷纲再排章。

## 两档章纲深度

**当前卷（马上要写的那一卷）**：每章都要 `title` + `brief`（60–100 字）+ `outline`（主目标变化 / 冲突 / 章末钩子）+ 三个引用。这是"能直接开工"的深度。

**后续卷（还没轮到的卷）**：每章都要 `title` + `brief`（40–60 字，只写"这章发生什么、局面怎么变"），`outline` 留空。等该卷进入当前卷时，再逐章补 `outline` 与引用。

这样既满足"每卷每章都有标题和梗概"的全景要求，又不会把后面几十章写死。**标题和梗概是骨架，章纲是施工图；骨架可以先全部立起来，施工图按卷出。**

## 闸门（出现下列情况，先停下补规划，不要继续往下写）

1. 当前卷没有卷合同，或有合同但"禁止提前完成"为空。
2. 卷末没有未解决的矛盾，说明这卷写完就无事可做。
3. 下一卷还没有标题与梗概，却已经开始写当前卷末尾（会逼着作者临时想结局）。
4. 章纲里出现卷合同"禁止提前完成"清单里的事件。
5. 章纲与已经写出的正文事实冲突（见下节，冲突时改规划，不改历史）。

## 计划态与事实态（硬规则）

两类东西必须分开，任何情况下不许互相污染：

| | 计划态 | 事实态 |
|---|---|---|
| 内容 | 总纲、卷合同、后续卷标题梗概、章纲 | 已写章节正文、角色当前状态、伏笔状态、已结算事件 |
| 能不能预写 | 可以，允许只到粗粒度 | 不可以，没写出来就不许写成已发生 |
| 冲突时谁让 | **计划让事实**：回来改卷合同或章纲 | 事实不让：不许为了自圆其说去改已发布的章节 |

具体到本应用：

- `/chapters` 的 `title` / `brief` / `outline` 是**计划**；`content` 是**事实**。
- `CharacterProfiles.current_state` 只在角色真的经历了某事之后更新，不许按大纲提前写"他这时候已经黑化"。
- `Foreshadowings.status` 走 `pending → planted → payoff / abandoned`，状态只随正文推进，不许按计划提前置为已回收。
- 正文里冒出的、大纲没写的新设定：回写世界观条目与角色卡，并在章纲里标注"新增"，**倒灌方向是正文 → 设定**，不是设定强行覆盖正文。

## 与本地工具的映射

## 与"每章都要有标题"的关系

上游默认只仔细纲到当前窗口，是为了防止写死。本应用要求**全部卷每章都有标题和梗概**，两者不冲突：把"标题+梗概"当作全书骨架一次立起来（成本低、改动代价小），把"章纲"当作施工图按卷出（成本高、改动代价大）。改一个标题的代价远小于改一章章纲。
