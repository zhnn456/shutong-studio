# 同人初始化流程

在当前作品上下文中的 `type` 为 fanfic 时使用。同人可以取用原作人物与设定，但原著事实必须**有据可查**，不得凭模型记忆臆造 Canon。

整体顺序：框定**取材区间** → 建立一份**有据可查的原著参考大纲** → 在其上做**原创改写** → 交付 `SKILL.md` 定义的 L2 骨架（世界观、角色、分卷、逐章纲目）。骨架规范只在 SKILL.md 定义，本文档说明同人特有的边界与问法。

若发现这其实是「你自己前作完结后的承接」而非在原著时间线内取材，说明作品性质应为续作，提示用户改用续作流程。

## 1. 建立原作边界与取材区间

先读工作区中已有的人物、世界观与大纲线索。若「故事背景」中已有用户提供或确认的原作资料，先只做全局定位，不要在取材区间确认前通读完整时间线：

1. 从 `Read {"path":"/lore"}` 返回的实际路径进入「故事背景」，不要自行拼接嵌套资源路径。
2. 先读「原作名 - 剧情梗概」，了解全局主线和结局，作为框定取材区间的依据。
3. 用户提供或已核实的剧情梗概、完整时间线、每章剧情可作参考资料，不算模型记忆；须保留来源。资料缺失、为空、互相冲突或与用户指定版本不符时，必须说明缺口并 AskUser，不能自行补全 Canon。

用 AskUser 分轮确认：

1. 基于哪部原作或前作、哪个版本与时间范围（取材区间）
2. 必须遵守的人物、设定、关系与重大事件
3. 允许偏离的范围：分歧点、切入点、OOC 边界、是否改写原作结局
4. 原著素材是否充分：不足时要求用户提供或确认资料；模型凭训练记忆得到的部分标「待用户核实」

取材区间确认后按区间核对原作状态（用 Grep 定位章节标题再分页 Read，不批量读全量）：

1. 「完整时间线」中与区间相关的章节：核对事件顺序、因果、人物与世界的状态
2. 需要核对冲突、章末钩子时，再读「每章剧情」对应章节
3. 需要查证原文时按 `原文证据` 定位，`Read /works/{work_id}/chapters?chapter_num=N` 读 `content`
4. 摘要与原文冲突时列出来源与分歧并 AskUser，不默认任一方无条件优先

### 确认故事线位置（必选其一）

- **故事线之前**：原作开篇前，结局必须收敛到原作开篇的已知状态
- **故事线平行**：与原作同期，会交汇或错位
- **故事线之后**：从原作已知终点继续

三者不得混为同一个大纲。区分要点：

- 平行：在同一时间轴上逐拍改，标注分歧点
- 之前：原著大纲退化为「开篇已知状态」，前传收敛到该状态
- 之后：原著大纲退化为「结局状态」，续写从其后展开

## 2. 建立原著参考大纲（限定在取材区间）

目标不是还原原著全书，而是就取材区间建立一份基线。

- **区间限定**：只覆盖同人主线会触及的原著范围
- **来源限定**：只能总结自已提供或已核实素材；模型记忆产出的标「待核实」，不作为 Canon
- **不得机械照搬章节**：分卷/节拍服务于「哪里可改、哪里是硬 Canon」，不复述剧情，不复用原文或标志性表达
- **用户主导分卷**：AskUser 确认这份参考大纲切几段、每段覆盖范围

每段整理时按主角、题材与改编目标挑 2–5 项（可选维度，不是必填模板）：

- 硬 Canon 锚点：必须遵守的起止范围、重大事件、角色状态变化、死亡/失踪、信息揭示
- 可改编空间：不可改的硬设定与可自由发挥的留白，以及连锁影响的高风险节点
- 关系线与伏笔接口：可深挖的情感/权力/误解节点，可嫁接或反转的伏笔与原作回收点
- 名场面与情绪基调：可呼应、错位或反转的场景与情绪机会
- 与同人主线的接口：适合交汇、旁观、避开或制造分歧的节点

落成独立大纲轨道，标题标明用途（「原著参考：第 X 卷」）。需长期遵守的硬边界经确认后提炼为 AgentRule。

## 3. 在原著大纲上做原创改写

三种位置都要产出**经用户确认的候选大纲与节拍表**；确认前不写入工作区。

### 故事线平行

1. 汇总各段硬 Canon 锚点、可改编空间、伏笔与关系接口
2. 确认同人主角的独立目标、资源限制、交汇窗口，以及哪些原作事件只能旁观
3. 逐拍标注：分歧点从哪拍开始、改变了谁的目标/关系、蝴蝶效应波及哪些后续拍、哪些 Canon 结果仍须保留
4. 节拍表每拍说明「发生什么、改变了谁、关联或刻意错开哪个 Canon 锚点、调用了哪个可改编空间或伏笔接口」
5. AskUser 展示大纲与节拍表，请用户确认、修改或重做
6. 确认后：同人主线写独立轨道（「同人主线：第 X 卷」），与「原著参考」分开维护

默认八拍（题材不适用可合并或替换）：独立开局与主角目标 → 首个 Canon 阴影或旁证 → 平行线自己的触发事件 → 第一次交汇/擦肩/冲突 → 独立目标受挫必须选择 → Canon 大事件前后的介入或错位后果 → 平行线高潮付出代价 → 收束并与原作时间线对齐或分道。

### 故事线之前

确认起点距原作开篇多远、铺垫边界、接入原作的节点、接入后是否继续写。核心约束：**前传结局必须收敛到原著开篇的已知状态**。末拍对齐原著开篇，AskUser 确认后落盘。

### 故事线之后

确认承接的原作终点、角色现状、未解决后果、新主冲突；原作结局是否可改必须显式确认。首拍承接终点并给出新主冲突，中段呼应前作主题而不重复，高潮回应遗留问题。

## 4. 交付 L2 骨架（同人版）

按 `SKILL.md` 第 5 节五段执行，差异只在内容来源：

- **A 世界观 5 条**：原作世界规则照抄 Canon 并在条目里写明「原作 Canon」；改编部分单列「可偏离范围」；不得把待核实内容写进世界规则
- **B 角色 6–8 张**：原作角色填 Canon 已知项，未知项标 `[推演]` 并注明依据；原创角色必须有独立功能位，不许只做原作的影子
- **C 分卷大纲**：每卷必须标出触及的 Canon 锚点与分歧点，读者能看出「哪一段原作被改了」
- **D 逐章纲目**：每章引用必须包含「关联 Canon 锚点」；与原作同期发生的章要标出「此时原作进行到哪」
- **E 自检**：SKILL.md 的 5 条 + 追加 2 条：
  6. 每条章纲的 Canon 锚点都能在原著参考大纲里找到依据
  7. 没有把「待核实」素材当成 Canon 写进正文级内容

## 5. 完成通用初始化

原作边界与故事线位置确认后，再确认题材、读者、故事承诺、书名、分类、标签、简介与通用写作约束（7–10 条 AgentRule）。

同人可采用原作人物与设定，但不得把原作正文、标志性段落或具体表达当作可复用素材。文风描述为可执行的写作特征，不要求复刻原作句子。

## 6. 结束检查

- 原作范围、Canon 锚点、允许偏离的范围是否清楚？
- 原著参考大纲是否基于已核实素材、按用户确认的分卷整理、未混入臆造 Canon？
- 故事线位置是否唯一且与时间线一致？
- 候选同人大纲与节拍表是否已确认并落盘？
- 同人主线是否与「原著参考」轨道分开维护？
- **L2 五段是否齐全，自检 7 条是否全过？**
