# 创作向导

开书的交付物不是"几条写作规则"，而是一套**能直接开工的骨架**。用户点开书是为了拿到成品，不是为了答题，所以本技能的原则是：

> **少问，多给：3 轮硬决策 → 一次性出全套骨架 → 用户改 → 确认落盘。**

AgentSkill 是应用内全局可复用的 AI 工作流程，不是作品规则或故事事实。它负责规划、写作、设定、审查、润色等任务，可在任意小说聊天中按需加载；执行产生的内容仍须分别写入当前小说的 AgentRules、作品元数据或工作区资料。

适用于新建引导，也适用于已有书名、简介或分类的作品重新整理——先读已有内容，再让用户确认保留或调整，不要当成「只能给空白书用」。

## 交付标准（三层，缺一层不算完成）

| 层 | 内容 | 何时交付 |
|---|---|---|
| **L1 地基** | 作品元数据（书名/分类/标签/简介）+ 写作行为 AgentRule 7–10 条 | 第 3 轮硬决策后立即落盘 |
| **L2 骨架** | 世界观 5 条 + 核心角色 6–8 张完整卡 + 分卷大纲 + 每卷每章标题与梗概 | **开书必须交齐，缺一不可** |
| **L3 精修** | 场景级 beat、关系图、伏笔回填、关键台词 | 开书之后按卷点，不进开书 |

**一键开书 = L1 + L2 全绿。** 只有 L1 没 L2 的开书不算完成，不得回报"基础引导完成，可随时从排章起步"。

## 不适用（已加载后仍须遵守）

若当前任务属于下列情况，停止继续引导，改走对应路径：

- 用户只问技术、数据库、UI 操作问题，或当前任务不涉及小说内容创作。
- 当前小说已完成 L2 骨架且用户未要求重新引导；继续按现有 AgentRules 与资料写作即可。
- 用户要的是审稿、扩写、节奏检查等具体写作任务，应优先匹配对应 AgentSkill。
- 当前作品上下文中的 `type` 为 material（资料）时；它不是待写作的小说，不需要本引导。

## 工作流程

### 1. 前置准备：先读，再问

提问前必须先收集已有信息：

1. 从系统提示「当前作品工作路径」取当前作品地址，将下文的 `/works/{work_id}` 换成该地址。读取小说元数据：`Read {"path":"/works/{work_id}"}`（`title`、`description`、`category`、`tags` 等），并读取聊天系统提示「当前作品」段中的 `type`。
2. 调用 `Run {"command":"agent-rules","subcommand":"list","options":{}}` 查看已有 AgentRules。
3. 调用 `Run {"command":"agent-skills","subcommand":"list","options":{}}` 查看应用内全局已安装的 AgentSkill。
4. 浏览工作区资料：世界观（`/lore`）、角色、势力、大纲、已有章节，识别哪些事实已经存在。
5. 建档缺口清单：L1 缺什么、L2 五段各缺什么、哪些已有资料可复用、哪些不可被覆盖。

已有内容一律不重问；已有 AgentRules 与当前方向一致时不要重复问同样规则。

### 2. 选择创作模式与按需附件

先选一个且只读一个创作模式附件。正文已有准确附件路径时直接用 `reference-get` 读取；未知路径时，再用 `<skill_resources>` 中的 `Run agent-skills reference-list` 列目录并从返回的 path 中选择；禁止臆造路径或预读全部附件。

- `type` 为 fanfic：读同人流程附件。
- `type` 为 sequel：读续作流程附件。
- `type` 为 original：上下文已明确从零创作 → 原创流程；已明确要学习某部作品的开篇/结构/节奏/文风 → 仿写流程；否则先用 AskUser 问「从零原创」或「仿写技法」。
- 用户说"仿写"但保留原作世界、角色、关系、剧情线或关键设定时，说明这属于同人/衍生，不按仿写流程继续。
- 附件不存在、读取失败或不能支撑当前分支时，直接报告失败，不得假装初始化完成。

**所有模式最终都必须交付本技能定义的 L2 骨架。** 附件负责模式特有的根决策（承接边界、Canon 锚点、技法清单），骨架规范只在本文档定义一处，附件不得各写一套。

### 3. 只问三轮硬决策

**第一轮 · 方向**：题材与目标读者、一句话故事承诺、主角核心目标与核心对立。

**第二轮 · 量级与分卷**：全书篇幅量级（目标章数/万字量级）、分几卷、每卷大致章节范围。这是 L2 分卷与章纲的锚点，没有量级就无法合理估章。

- 建议切法：<50 章不分卷或 2 卷；50–150 章 3–5 卷；>150 章 5–8 卷。
- 卷数与范围由用户主导，AI 可建议但不得擅自定卷。

**第三轮 · 不可逆结构**：按题材只挑 2–3 个最关键的维度，确认后即停止提问。

- 世界/舞台与社会秩序
- 能力/资源体系及其硬上限与代价
- 势力与关系格局
- 信息边界（谁知道什么）
- 现实、史实、行业或科学边界

**每轮 2–3 个问题，用 AskUser，每问 2–4 个 options 并标一个 `recommended: true`，允许自由输入。** 不要一次抛出整张清单，也不要为补全模板追问细枝末节。

**不要为了"环节完整"再加第四、第五轮。** 缺的信息用 L2 草案补，再让用户改——这比多问十轮更快拿到成品。

### 4. 载体分流（元数据、规则、故事事实，不许混写）

**作品元数据** → 直接写 `/works/{work_id}` 下字段：`title`、`category`、`tags`（逗号分隔）、`description`。展示现值让用户确认，未经 AskUser 不得覆盖。

**加入书架**：若 `Read /works/{work_id}/draft` 返回 true，在书名与方向确认后用 AskUser 问一次是否现在加入；同意则 `Write .../draft` 为 false。

**写作行为约束 → AgentRules**（7–10 条，一条只管一个维度，可执行、不含空话）：

- 章节字数、文风、叙事视角、节奏、章末钩子
- 禁忌与长期写作边界（不降智反派、不强行误会、不用 AI 腔过渡词）
- 从已有资料提炼的候选规则：AskUser 必须说明候选内容、来源资料、写入后后续写作都会参考，用户明确确认后才能写入
- 写入：`Run {"command":"agent-rules","subcommand":"create","options":{"name":"<标题>","content":"<规则内容>"}}`

**故事事实 → 工作区资源**（不得写成 AgentRule）：

- 世界观条目 → `/lore`
- 角色档案 → `/characters`
- 势力档案 → `/factions`
- 大纲轨道 → `/outlines`（卷级）、beat（章级节拍）
- 章目 → `/chapters`（标题、章纲、梗概）

若某条事实同时需要 AI 严格遵循，可在写入资源后再确认提炼一条 AgentRule，但事实载体仍是工作区资源。

### 5. L2 骨架生成（本技能的核心，五段，缺一不可）

硬决策确认后立即开始，**不要停下来问"要不要继续"**。每段生成完即落盘（防取消丢失），落盘后再向用户展示摘要。

#### A. 世界观 5 条（每条 150–300 字，独立条目写进 `/lore`）

1. **世界结构与时代**：地理、空间、时间锚点，读者一进来看到什么
2. **秩序与制度**：谁掌权、规则怎么运行、普通人怎么活
3. **力量/能力体系**：能力的来源、硬上限、代价、禁忌（多重能力体系要各自写清上限与代价）
4. **势力格局 3–5 家**：每家目标 + 彼此冲突 + 与主角的关系
5. **信息边界**：谁知道什么真相，何时揭示，读者比角色多知道什么

任一维度与题材无关时，用有依据的推演填充并标 `[推演]`，不得留空。

写入用 `Create /lore`：`title` 一条一主题（如「力量体系：借兵的代价」），`content` 写正文，不要把 5 条塞进一个条目。

#### B. 核心角色 6–8 张，每人 9 字段全填，一空即不合格

| 字段 | 要求 |
|---|---|
| 身份与年龄 | 具体职务/社会位置，不是"神秘人" |
| 外貌 | 一个可辨识特征（疤、瘦、旧甲、手上有墨） |
| 性格 | 3 个可观察行为标签，不是形容词堆叠 |
| 想要什么 | 具体可执行的目标，能推动剧情 |
| 怕什么 | 具体恐惧，能成为被攻击的软肋 |
| 不会做什么 | 底线，决定他的选择边界 |
| 能力与资源 | 他凭什么能做到；对应力量体系里的上限与代价 |
| 与主角的关系张力 | 不是"朋友/敌人"，而是"他需要主角但会为 X 背叛" |
| 弧光 | 从哪到哪，首末状态可对照 |

**写入参数映射（按 `Create /characters` 实际字段传，不要自造参数名）**

| 9 字段 | 写入参数 |
|---|---|
| 身份与年龄 | `identity`、`age` |
| 外貌 | `appearance` |
| 性格 | `personality` + `behavior_tags`（`[{tag, context}]`，每条给可观察行为） |
| 想要什么 | `motivation` |
| 怕什么 / 底线 / 能力与资源 / 关系张力 | 没有独立字段，合并写进 `description`，用分句标出（「怕：…」「底线：…」「能力：…（上限…代价…）」「与主角：…」） |
| 弧光 | `arc` |
| 功能位 | 写进 `tags`（如 `["对手","信息源"]`），不要硬塞进 `role` |

`role` 只取四个枚举值：`protagonist` / `antagonist` / `supporting` / `minor`。功能位是叙事角色，不是数据库角色，两者不要混用。

**功能位铁律：每个核心角色必须占一个叙事功能位，占不到就删掉。**

- **对手**：合法地阻止主角，动机站得住
- **推进器**：给主角手段/资源/机会
- **镜像**：同一处境下的另一种选择，反衬主角
- **信息源**：知道真相的一部分
- **代价**：主角的选择会伤到的人

若某个能力体系只有主角一人拥有，把它的"来源、代价、禁忌"写进世界观第 3 条，不要只挂在角色卡上——否则后面会写成无敌挂。

#### C. 分卷大纲（两件事都要做：建卷节点 + 写大纲轨道）

**① 章节树的卷节点**：`Create /volumes`，`title` 用卷名（如"第一卷　天竺劫"），`outline` 传卷简介。这一步决定章节能不能挂到卷下——不建卷节点，120 章会全部平铺在根目录。

**② 大纲轨道**：`Create /outlines`，每卷一条，400–600 字。

每条必须包含：卷目标、三步推进（起—转—收）、卷末反转或代价、与下一卷的交接钩。

- 轨道字段：`title`（如"主线：第一卷　天竺劫"）、`content`、`start_chapter_num`
- 卷与卷的 `start_chapter_num` 必须连续无缝，不重叠不留空
- 标题表达用途，不设父子关系；"全书总纲"可只写全书结构
- 卷节点（章节树）与大纲轨道（规划文本）是两套东西，同名同序，不要只建其中一个

#### D. 逐章纲目（每卷每一章，标题 + 梗概 + 三个引用）

这是"联动"的落地点。每章一条，写进 `/chapters`：

- **标题**：不用"第 X 章"充数，要有信息量（如"三十一人一夜蒸发"）
- **必传 `volume_id`**：用 C 段建好的卷节点 id，否则章节会按"最新一章"顺延，跨卷时挂错
- **梗概 `brief`**：60–100 字，写"谁做了什么、局面变成什么"，不写抒情
- **章纲 `outline`**：本章唯一主目标变化 + 冲突 + 章末钩子
- **三个引用**：出场角色（必须已在 `/characters`）、涉及势力（可选）、埋设或回收的伏笔（必须能配对）
- 只建章不建正文，`content` 留空（正文由章节写作流程负责）

超过 35 章的卷分批生成，单批 ≤35 章；每卷生成后 AskUser 确认一次，确认后再落下一卷。**不要一次性铺完 120 章再问**——分卷思路一改就是全量返工。

> 200 章以上的书：L2 默认只把前 3 卷铺到章，其余卷只交卷纲，并在回报里说明"后续可一键补齐"。

#### E. 骨架自检（不过就不许交付）

生成完按下列 5 条自查，任一条不过就回炉补，补完再报：

1. 章纲里出现的每个角色名，都能在 `/characters` 查到（幽灵角色 = 不合格）
2. 每条伏笔都有 setup 章与 payoff 章，且 payoff 章号 > setup 章号
3. 各卷章数之和 = 全书章数；`start_chapter_num` 连续
4. 每个核心角色至少 3 章登场，首次登场不晚于第一卷
5. 力量体系写下的上限与代价，章纲里没有无代价突破

自检结论要写进回报，让用户看到"过了哪几条"，而不是只说"已完成"。

### 6. 能力配置（L2 交付之后）

只在骨架交付后处理，不预装所有技能：

1. 先看已有全局 AgentSkill，已装且启用、职责匹配就直接用其 `call_name` 调用。
2. 基础创作能力缺失时，读一次官方目录 `Run {"command":"agent-skills","subcommand":"search","options":{"source":"official"}}`，按"章节规划""正文写作""跨章节连续性"等能力方向挑候选；该命令不支持按 query 过滤，只调一次。
3. 用 AskUser 说明每项名称、用途、安装后全局可用的影响；用户可整包、部分或暂不安装。只有确认的候选才 `install`。
4. 安装返回 `already_exists`：AskUser 选覆盖（`conflict_resolution: "overwrite"`）、新 `call_name` 或取消，不得自行覆盖。
5. `marketplace` 返回 `unavailable` 时如实说明市场未接入，保留本地候选或列为待补齐。
6. 用户拒绝安装不阻塞交付，列进回报的缺口清单。

### 7. 完成与回报

**完成判据只有一个：L2 五段（世界观、角色、卷纲、逐章纲目、自检）全部落盘且自检通过。** 不得以"基础决策已确认"作为完成。

回报格式（简短、按事实）：

- 已写入元数据（书名/分类/标签/简介）
- 已创建 AgentRules（按维度列出条数与名称）
- 世界观条目数、核心角色数与功能位分配、卷数与章数（如"4 卷 120 章，第一卷 30 章已铺到章"）
- 自检结果：5 条各过/不过
- 未解决缺口（含 200 章以上未铺完的卷、未安装技能、`[推演]` 待确认条目）
- 下一步建议（用 `SuggestNextAction` 挂一次，最多 3 条，seed 必须来自本轮实际落盘内容）

`SuggestNextAction` 候选：排开篇三章（`kind=prompt`，写明基于哪几条设定）、补下一卷章纲（`kind=prompt`）、去小剧场演开篇首场冲突（`kind=feature`）、去圆桌讨论分卷切法（`kind=feature`）、和已写入的角色卡角色聊两句（`kind=feature`，seed 写角色名）。

Run 失败时直接报告失败原因，不要说"已保存"，也不得用普通回复代替持久化。

## 提问原则

- 必须用 AskUser 交互提问，不要输出问题列表等用户回复。
- 按依赖顺序分轮，一轮 2–3 个相关问题；先问决定其它项的根决策。
- 每个问题 2–4 个 options，标一个 `recommended: true`，允许自由输入。推荐只是降低回答成本，用户未选前不算确认、不写入。
- 用户说"你来定"：把建议汇总成一套并**标注为建议**，请求确认后再落盘。
- 用户只回答一部分：只沉淀已确认的，其余缺口进清单，不编造默认值代替。
- 发现新回答与旧 AgentRules 冲突：直接指出冲突让用户选，不得平均处理。
- **不要为了显得严谨而增加提问轮次**；能靠 L2 草案暴露的缺口，一律用草案解决。

## 每轮即落盘（硬规则）

每一段产出结束立刻写入对应载体，不要攒到最后统一写。向导可能被取消、超时、被打断，或用户中途改方向；攒着写的结果就是整本书只剩正文、没有设定。

## 取消 / 超时 / 打断的语义（硬规则）

- 处理顺序固定：先落盘已确认与已生成内容 → 再停止追问 → 最后说明"已写入哪几项、还缺哪几项"。
- 取消只表示"不再继续"，不等于前面答的全部作废。禁止因为一张卡片被取消就把整轮设定判为未确认而全部不写。
- 用户已明确回答的元数据与写作约束必须写入；未回答项留空并进收尾清单，不得编造默认值。
- 取消后不再追加提问；剩余缺口等用户主动要求时再补，并说明"可以从第 X 段续做"。

## 推演与确认

- 世界观与角色里没有用户依据的部分，标注 `[推演]` 并给出依据（哪条已确认设定推出这个结论）。
- `[推演]` 内容写入资源时保留标记，便于用户后续筛选修改；不得把推演包装成既定事实。
- 与原作 Canon（同人）或用户已确认设定冲突的内容，一律不得写入。

## 默认建议

`recommended` 选项与"你来定"汇总的基准（结合元数据与已确认回答调整，确认前不作为规则）：

- 章节字数：2000–3000 字，允许上下浮动 10%
- 文字风格：清晰、克制、有画面感，少用空泛抒情和总结句
- 叙事视角：第三人称单主角，严格遵守信息边界
- 节奏：每章至少推进一个明确变化，章末留钩子
- 禁忌：不降智反派、不强行误会、不用 AI 腔过渡词、不用大段解释代替行动
- 分卷：按量级 4–6 卷，每卷 25–35 章

## 边界（不做清单）

- **不写正文**，一章都不写；正文交给章节写作流程。
- **不拆场景级 beat**（那是排章阶段的活），L2 只到章。
- **章梗概不超过 120 字**，再长必被改且拖慢。
- **核心角色 ≤8，功能配角 ≤10**，多了一律合并或删除。
- **不因模板完整而硬造设定**：无依据的一律标 `[推演]`，不伪装成事实。
- **不擅自改用户已确认的卷数与章数**。
- AgentSkill 不保存故事事实，也不替代 AgentRules；执行产出必须写回正确载体。
- AgentSkill 全局可用，但不得硬编码当前小说的故事事实。
- 初始化无法预测用户未来的全部任务；后续突发需求由聊天路由或「系统管理」技能管理附件处理，不要求本技能预装全部能力。
- 日常 AgentRules / AgentSkills 的增删改查走「系统管理」附件；本技能只负责 Onboarding 期的沉淀与骨架编排。
- `创作向导` 无对应 Run 命令；只能通过 AgentSkill tool 加载，或由聊天系统在初始化阶段主动触发。
