# 书童AI工作台 · 写小说流程设计与功能打通计划 v3

日期：2026-11-17
基线：`unstable` 分支，0.10.0 已合并；本日已实施 P0-0-A(提示词层) / P0-0-B(互锁)
定位：本篇不重复 v2 的问题清单，专答两件事——
1. **一本书应该怎么被写出来**（流程与状态机）；
2. **软件里 17 个页面为什么各干各的**，以及怎么用"站间契约"把它们串起来。

---

## 0. 一句话结论

我们不缺功能，缺"交接单"。17 个工作区页面全齐（`novel_workspace.dart:142`），
但**没有任何一处规定"上一站的产物必须变成下一站的输入"**，所以每个页面都只是一个孤立的编辑框；
正文写出来了，设定库仍是 0——不是能力缺失，是**流程没有状态、没有产物、没有闸门**。

对标竞品后最该拿的一条：Sudowrite 的 Story Bible、马良的三级大纲、Novelcrafter 的 Codex 自动提及、
AI_NovelGenerator 的 readiness 门控——四家做的是同一件事：**每一步都有产物，产物决定下一步能不能走**。

## 1. 先看清"脱节"到底发生在哪（已核实）

| 现象 | 代码事实 | 造成的断裂 |
|---|---|---|
| 写了两章，角色/伏笔/世界观/大纲全空 | 这些表只有两种写入途径：UI 手点新建、或 AI 调 `Create`（`tools_create.dart:193-200` 支持 characters/locations/foreshadowing/outlines/lore/materials）。写作链路里**没有任何一步**往里写 | 正文与设定库之间没有管道 |
| "写后回填"没发生 | `chapter-write-pipeline/SKILL.md:27-29` 要求"列成待回填清单等用户确认"；界面无承接清单的容器，只有快捷指令文本里提过（`ai_shortcut_action.dart:301`） | "等确认"没有 UI 落点 = 不发生 |
| 章节事件永远为 null | `chapter.dart:22,24` 只有 `draft/published`；`chapter_editor.dart:215` 注明 tension/emotion/events 由 chronicler **发布后**回填 | 只要不定稿，编年史者就不工作 |
| 写完一章没有下一步 | 全库"下一章"只命中阅读模式翻页（`reading_page.dart:702`）与编辑器章节切换 | 作者只能自己再发一句指令 |
| 上下文越写越贵 | 窗口 200k、压缩阈值 0.8（`agent_context_manager.dart:21,26`）；复验单次 48,929 / 33,835 token | 第 10 章起注意力与成本双崩 |

## 2. 竞品在"流程"上做了什么（只取能落地的四条）

| 竞品 | 关键机制 | 对我们的启示 |
|---|---|---|
| **Sudowrite** | Story Bible 驱动全流程；写章自动带 Bible 摘要；Chapter Continuity 跨 25 章；Series Folder 跨书共享 | 设定不是文档，是**注入器**：写章时按需取，不靠模型记忆 |
| **Novelcrafter** | Codex 条目能被"自动提及"，也可 **Exclude from AI** 排除；版本历史 | 每个设定条目要能"被引用/被排除"，写章可解释"我用了哪 6 条" |
| **马良写作** | 三级大纲（世界观→卷→章）；7 Agent 分模型；逐段保留/还原 + 一键撤销本轮 | 大纲必须分三级且能被写章读取；改动必须可回退到"段" |
| **AI_NovelGenerator** | `get_writing_readiness` 就绪门控；受控白名单上下文；节点图流程 | 缺前置就**拦住**，不是劝告；上下文用白名单而不是全量 |
| **阅文作家助手** | 伏笔分布图、章节状态、发布衔接 | 伏笔要有"埋在第几章 / 该在第几章收"的分布视图 |

共性：**四家都不靠"模型自觉"，都靠产品级状态与门禁。**

## 3. 我们要的流程：七站式，每站一个产物（核心设计）

设计原则：
- 每站有**唯一产物 + 唯一落点表**，产物存在即下一站可走；
- 每站有**跳过选项**（作者可控，不强制全填），但跳过要在概览留一条"欠账"；
- 每站结束都有**「下一步」卡**，由代码按状态计算，不靠模型附建议；
- 不新增页面类型（v2 结论不变：缺口在联动与可见性，不在字段）。

```
立项 → 世界观 → 人物 → 大纲 → 章纲 → 写章 → 沉淀 → 定稿/审校 → 下一章
 0      1        2      3      4      5      6         7            ↺ 回到 4
```

| 站 | 名字 | 产物（必须落库） | 落点 | 进入条件 | 完成判据 | 对应竞品 |
|---|---|---|---|---|---|---|
| 0 | 立项 | 一句话卖点 + 类型 + 目标字数 + 主角名 | `agent_rules`（书级规则） | 有书名 | 4 项非空 | Sudowrite 分步 Bible 第 1 步 |
| 1 | 世界观 | 3–5 条：世界规则 / 主要势力 / 禁忌或代价 | `documents(type=lore)` | 站 0 完成 | 至少 3 条 | NovelAI Lorebook |
| 2 | 人物 | 主角 + 2–3 配角卡：目标 / 弱点 / 秘密 / 说话特征 | `character_profiles` | 站 0 完成 | 主角卡非空 | 马良角色卡 |
| 3 | 大纲 | 两级：卷（3–5 个）/ 每卷 8–15 章标题 + 一句话 | `outlines` | 站 1、2 完成或明确跳过 | 卷数≥1 且章条目≥8 | 马良三级大纲 |
| 4 | 章纲 | 本章目的（只一个）/ 出场人及状态 / 冲突 / 章末钩子 / 埋·收伏笔 | `outlines`（chapter 级节点） | 有对应大纲条目 | 5 字段齐 | Sudowrite Chapter Outline |
| 5 | 写章 | 正文 + 字数 + 自查结论 | `chapters.content`（`stat=draft`） | 站 4 完成 | 正文落库且字数达标 | 通用 |
| 6 | 沉淀 | 角色状态变化 / 新伏笔 / 未回收线索 / 设定补充 | `character_profiles` `foreshadowings` `story_progress` | 站 5 完成 | 清单被确认或明确忽略 | 马良"更新档案" |
| 7 | 定稿 | 章 `stat=published`；chronicler 回填 events/tension/emotion；全书审校报告 | `chapters` + 报告 | 站 6 结束 | 状态变更 | 阅文章节状态 |
| ↺ | 下一章 | 回到站 4，自动带上一章结尾与未回收伏笔 | — | 站 7 完成 | — | Sudowrite Continuity |

### 3.1 站间契约（这是"打通"的全部含义）

| 契约 | 内容 | 现在有没有 |
|---|---|---|
| C1 设定→写章注入 | 写第 N 章只注入：近 2 章摘要 + 出场角色当前状态 + 未回收伏笔 Top3 + 本章章纲 + 世界观命中条 | 无（全量注入） |
| C2 章纲→写作门禁 | 无章纲节点时，「写本章」按钮置灰并给"先补章纲" | 无 |
| C3 正文→沉淀 | 落库成功后自动生成"待回填清单"卡，一键确认写入 | 无（只写在技能里） |
| C4 沉淀→角色状态 | 角色卡有 `currentState` 字段供下一章读取 | 有卡无状态演进约定 |
| C5 定稿→编年史 | 定稿即回填 events/tension，不等"发布"语义 | 有但触发点错 |
| C6 状态→下一步 | 概览/编辑器按"七站完成度"算下一步卡 | 无 |

### P0（1–2 周）· 让 0→5 站第一次就能走通
> 目标：新用户从"点开始"到"第 1 章落库"，全程不需要记住任何指令。

| P0-6 | 下一步卡 + 七站进度（概览/编辑器） | `novel_overview.dart:1227`、`workspace/hero.dart` | 每站结束自动指向下一站 |

### P1（3–6 周）· 把 6–7 站闭环，并让作者能控制 AI
- 逐段保留/还原 + 一键撤销本轮（复用 `working_changes`）；
- `@` 引用资料进写章（复用 `canvas_resource_picker.dart` 的选择器）；
- 全书审校报告（带位置跳转）；
- 文风 DNA（3–5 段样文 → 句长/连词密度/禁用套路，常驻注入）；
- 成本可视化（本轮/本书累计/上下文占比）；
- 伏笔分布图（埋第 N 章 / 应在第 M 章收）；
- 定稿触发编年史（`chapter_editor.dart:215` 的触发点从"发布"改"定稿"）。

### P2（1–2 个月）· 拉开差异化
- 导出 DOCX / EPUB / 投稿格式检查（`novel_export.dart:385`）；
- 系列与宇宙：跨书共享 lore / 角色（对标 Sudowrite Series）；
- 平台档位（番茄/起点/晋江字数与断章参数）+ 拆书仿写公共库；
- 可视化编排（复用 canvas 节点图，对标 AI_NovelGenerator）；
- 全书问答（复用 embedding + entity_graph，答案带章节引用）。

### 明确不做（延续 v2）
不自研模型；不做社交/拼字/稿酬；不把向量 RAG 当主线；不新增设定页类型。

## 6. 状态机设计（P0-6 的技术前提）

```
chapter.stat:  draft → writing → reviewed → published
                ↑ 写章中      ↑ 审查通过   ↑ 定稿（编年史回填）
outline.node:  大纲条目 → 章纲(5 字段) → 已写(引用 chapterId) → 已沉淀
book.stage:    0 立项 / 1 世界 / 2 人物 / 3 大纲 / 4 章纲 / 5 写章 / 6 沉淀 / 7 定稿
```
规则：`book.stage` 只由产物计算（查表得出），不允许手工置位；`chapter.stat` 只由写章/审校/定稿三个动作推进。

## 7. 执行顺序（建议）

1. 分支 `feat/flow-gates`（不动 unstable 直到验证通过）；
2. 先做 **P0-5/P0-7/状态机字段**（写作侧骨架），再 **P0-6 下一步卡**（UI 心跳），最后 **P0-1/2/3**（入口与成本）；
3. 每步验收：`flutter analyze --no-pub`（基线 0 error/0 warning）、相关测试与基线一致、构建成功；
4. 端到端脚本：新建书 → 三站向导 → 建大纲 → 写 2 章 → 确认沉淀 → 查库里四张表非空（这是本计划的总验收）。

**总验收（一句话）**：写完第 2 章后，`character_profiles ≥ 3`、`foreshadowings ≥ 2`、`outlines ≥ 9`、`lore ≥ 3`、`chapters = 2 且 stat=reviewed`——复验里那四个 0 全部消失。

## 8. 风险

1. **状态字段迁移**：`chapter.stat` 扩值要兼容旧数据，读侧需 `default: draft`；
2. **沉淀卡可能变成噪音**：每章都弹会烦，需"无变更不弹"；
3. **12k 预算 vs 文风样本**：样文常驻会挤占预算，需给样文单列上限（建议 2k）；
4. **上游继续横向扩张**：新页面会再增契约缺口，故"站"定义要写进技能文档，让 AI 侧也遵守；
5. **AGPL-3.0**：本计划全部为自有代码，不引入上游之外的新依赖；若后续引三方库需保留版权声明。

---

## 9. 与 v2 的关系

v2 是"问题总账 + 分阶段修复"；本篇是把 v2 的 P0 项**重排成一条有状态的流程**，并补上 v2 没写的三项：
- 七站模型与站间契约 C1–C6；
- 章节/书级状态机；
- 竞品机制→我们的对应动作映射（Sudowrite Bible → 注入器；马良三级大纲 → 大纲两级+章纲；Novelcrafter Exclude → `excludeFromAi`；AI_NovelGenerator gate → 写章置灰）。
