智能体规则 · 页面与规则库改造方案

四个排布方案 + 数据模型建议。可先挑方案编号，再细化到像素与交互。

要解决的两件事

1. 规则库是弹窗，看不全 760×480 的双栏弹窗，左栏 25 个包挤在 420 高里，右栏每条规则只露 4 行，分类要靠滚动找。
2. 规则堆成一大片，没有体系；详情页空 导入 12 条后就是 30+ 张同构卡片平铺（3 列网格），看不出层次；点进去只有「名称 + 一段富文本」，剩下大半屏空白，点击成本白花。

根因不在排布，而在数据：规则只有 id/name/content/enabled/sortOrder，没有「分组、来源包、一句话主张、示例、检查项」。排布只能靠猜。所以四套方案都要先补一层结构化字段。

我的推荐：A 打底，吸收 C 的两点

你的两个痛点分别是「看不全」和「点了白点」。A 用三栏把两者一次解决：左树给体系、右栏常驻详情让每一次点击都有收成；规则库与规则页同构，不再有弹窗。再把 C 的「跨包勾选 + 已选汇总」搬进 A 的右栏，就同时具备批量导入的爽感。

配套数据模型（四套方案都需要，只是字段多少不同）

字段说明来源
group体系维度：题材定位 / 结构节奏 / 人物视角 / 文风语言 / 逻辑约束 / 禁忌清单 / 考据制度导入时由包配置指定；手写规则可自动归类，也可拖动改
sourcePackId / sourcePackName来源徽标，支持「从规则库导入 12 条」一键撤销导入时写入
summary一句话主张，列表行显示，避免长文塞进一行包 JSON 新增字段；存量取 content 首句
examples正例 / 反例各 1～2 条包 JSON 新增；存量可留空
checks3 条自检项，用 □ 呈现，写章后可勾包 JSON 新增；存量可留空
sortOrder组内序号，保持现有字段已存在

落地顺序（选 A 时）

  1. 数据层：novel 库 schema +1，加 group/source/summary/examples/checks，存量规则按关键词回填分组
  2. 规则页三栏：左树（折叠记忆）、中列表（80px 行）、右详情（常驻，含试写按钮）
  3. 规则库整页化：分类树 / 包列表 / 勾选 + 已选汇总，替代弹窗
  4. 规则包 JSON 补 summary/examples/checks，导入时顺带写入 grouping

需要你定三件事：① 选哪套（A / B / C / D）；② 分组维度按上面 7 类，还是按「来源包」分组（悬疑推理包 / 短剧·都市逆袭包）；③ 详情面板常驻（A）还是抽屉（C）。定完我直接开工，不再来回问。
